# Реєстр агентів Antigravity

## Склад команди

| Агент | Фокус | Основний результат |
|---|---|---|
| Agent 0 — Lead / Orchestrator | План, інтеграція, статус, питання власнику | Узгоджені задачі, рішення в межах делегування, актуальна пам'ять |
| Product & UX | Вимоги, потоки, візуальна система й доступність | Специфікації екранів і станів, дизайн-рішення |
| Android UI | Compose екрани, компоненти, анімація, Glance віджет | Екрани/віджет згідно UX і погодженого контракту |
| Weather & Location | Моделі, погодне API, геокодування, кеш, дозволи | Надійний data/domain шар і документований API/ліцензія |
| QA & Privacy | Незалежна перевірка, дозволи, сценарії, доказ | QA звіт і `QA Verified` для чужої роботи |

## Як делегувати

1. Agent 0 розбиває roadmap на картки `docs/tasks/<ID>.md` із критеріями приймання, файлами-власниками та перевірками.
2. Залучає Product & UX до фіксації контрактів до паралельної реалізації UI і даних.
3. Паралелить лише різні шари/папки; UI та Data працюють за затвердженим контрактом, не редагуючи спільні файли одночасно.
4. QA отримує завершений diff/гілку від іншого автора. Якщо QA виявив помилку, автор виправляє її, а QA повторно перевіряє.
5. Agent 0 інтегрує, оновлює roadmap/state/board/session log і збирає питання власнику в одному inbox.

## Інструменти Antigravity

Файли `.agents/agents/*.md` є кастомними агентами, які Antigravity підхоплює з робочого простору. Відкрийте корінь проєкту; перевірте список кастомізацій у налаштуваннях або командою `/agents` у CLI. Схеми YAML можна уточнювати за офіційною документацією Antigravity; ці профілі навмисно використовують базові `name`, `description`, `model`, `tools` та `subagent`.
