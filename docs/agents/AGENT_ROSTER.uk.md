# Реєстр агентів Antigravity

## Склад команди

| Агент | Фокус | Основний результат |
|---|---|---|
| **Agent 0 — Project Lead / Architect** | План, інтеграція, архітектура, статус, журнал рішень, inbox Власника | Узгоджені задачі, архітектурні контракти, координація агентів, актуальна пам'ять |
| **Agent 1 — Product & UX Designer** | Структура меню, користувацькі сценарії, UX-аудит, візуальна ієрархія, дизайн-система, доступність | Специфікація інтерфейсу (`UX_SPEC.md`, `DESIGN_TOKENS.md`), доступність WCAG AA |
| **Agent 2 — Android UI Engineer** | Android UI, Jetpack Compose, анімації, теми (Day/Night), адаптивні екрани, UI-компоненти | Реалізація Compose-екранів, плавних анімацій, підтримок reduced-motion |
| **Agent 3 — Weather & Data Engineer** | Оцінка погодних API, ліцензії, геолокація, пошук населених пунктів, моделі, локальний кеш, мережа | Надійний data/domain шар, оптимізація мережевих запитів, геокодування, WMO-мапінг |
| **Agent 4 — Widget & Monetization Engineer** | Android App Widgets (Jetpack Glance), адаптивні розміри, графік оновлень, енергоефективність, рекламна стратегія | Робочий Glance-віджет, розклад оновлень без розряду батареї, безпечні Ad-плейсхолдери |
| **Agent 5 — QA / Security / Release Engineer** | Незалежний аудит, unit/integration/UI тести, контроль дозволів, приватність, Google Play compliance | Незалежний QA-звіт, статус `QA_VERIFIED`, перевірка релізних вимог |

## Як делегувати

1. Agent 0 розбиває roadmap на картки `docs/tasks/<ID>.md` із критеріями приймання, файлами-власниками та перевірками.
2. Залучає Product & UX до фіксації контрактів до паралельної реалізації UI і даних.
3. Паралелить лише різні шари/папки; UI та Data працюють за затвердженим контрактом, не редагуючи спільні файли одночасно.
4. QA отримує завершений diff/гілку від іншого автора. Якщо QA виявив помилку, автор виправляє її, а QA повторно перевіряє.
5. Agent 0 інтегрує, оновлює roadmap/state/board/session log і збирає питання власнику в одному inbox.

## Інструменти Antigravity

Файли `.agents/agents/*.md` є кастомними агентами, які Antigravity підхоплює з робочого простору. Відкрийте корінь проєкту; перевірте список кастомізацій у налаштуваннях або командою `/agents` у CLI. Схеми YAML можна уточнювати за офіційною документацією Antigravity; ці профілі навмисно використовують базові `name`, `description`, `model`, `tools` та `subagent`.
