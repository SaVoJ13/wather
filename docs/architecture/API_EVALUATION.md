## 1. Мета та контекст ревізії

Власник затвердив обов'язкову політику **ZERO BUDGET POLICY ($0 витрат на сервери, хостинг та API)** та підтвердив комерційну модель монетизації через **Google AdMob**.

### Обов'язкові функціональні вимоги продукту:
1. **14-денний щоденний прогноз погоди.**
2. **Погодинний прогноз (мінімум на 24–48 годин).**
3. **Геолокація за запитом користувача (GPS без фонового відстеження).**
4. **Пошук населених пунктів (міст та сіл) онлайн.**
5. **Інформативний Android-віджет (Jetpack Glance).**
6. **Офіційне право на безкоштовне комерційне використання з показом реклами AdMob.**
7. **Відсутність власного платного бекенду (Client-only архітектура на Android).**
8. **Гарантія відсутності прихованих платежів чи автоматичних списань (Zero Financial Exposure).**

### Чому WeatherAPI.com переведено в резерв:
Детальний аудит показав, що на безкоштовному плані WeatherAPI.com повертає **лише 3 дні прогнозу** (`forecast.json?days=3`). Спроба отримати 14 днів повертає помилку або скорочує відповідь до 3 днів; доступ до 14 днів вимагає переходу на платний тариф Pro ($15/міс, $180/рік), що прямо суперечить ZERO BUDGET POLICY.

## 3. Детальний аналіз та виправлення розрахунків Visual Crossing

### 3.1. Уточнення щодо розрахунку `queryCost` у Visual Crossing Timeline API
У попередній оцінці припускалося, що при виклику 15-денного прогнозу з погодинними даними Visual Crossing списує $15 \times 24 = 360$ records за один HTTP-виклик (як це відбувається при запиті історичних даних).

**Офіційне спростування та фактчек документації Visual Crossing:**
- У Visual Crossing Weather Timeline API параметр **`queryCost`** обчислюється по-різному для історії та прогнозу:
  1. **Прогноз погоди на майбутнє (Forecast):** Запит прогнозу погоди для однієї локації на будь-яку кількість днів (включно з повним 15-денним прогнозом та всіма 24 годинами для кожного дня) має **`queryCost: 1`**! Тобто списується рівно **1 record** за повний пакет прогнозу.
  2. **Історичні дані (Historical Data):** Лише історичні спостереження минулих періодів списують 1 record за щоденний запис або 24 records за добу погодинних даних.
- **Висновок:** Безкоштовний тариф Visual Crossing (1 000 records/добу) насправді надає **1 000 повноцінних 15-денних запитів на добу** (близько 30 000 запитів на місяць).
- Це робить Visual Crossing відмінним, повноцінно дієздатним **Кандидатом №2**.

### 3.2. Чому WeatherMetro Free залишається Кандидатом №1
1. **Обсяг безкоштовної квоти:** WeatherMetro надає **100 000 запитів на місяць** (~3 333 запитів на добу), що в **3.3 рази більше**, ніж добовий ліміт Visual Crossing (1 000 запитів/добу = ~30 000/місяць).
2. **Глибина прогнозу:** WeatherMetro надає до **16 днів** прогнозу (проти 15 днів у Visual Crossing).
3. **Формат даних:** DTO WeatherMetro повністю сумісні зі стандартами WMO, що спрощує уніфікацію з існуючими маперами.
4. **Гарантія $0:** При перевищенні ліміту WeatherMetro повертає суворий `HTTP 429 Too Many Requests` без ризику автоматичного білінгу.

## 4. Дослідження ризиків витоку API-ключа в Client-Only застосунку та захист ($0 Budget)

У мобільних застосунках без власного проксі-сервера (backend-less) будь-який ключ, що відправляється клієнтом, теоретично може бути перехоплений або видобутий з бінарного файлу.

### 4.1. Модель загроз (Threat Model)
1. **Статичний реверс-інжиніринг:** Декомпіляція APK через `jadx`, `apktool` або читання текстових рядків `strings classes.dex`.
2. **Динамічне перехоплення HTTPS-трафіку:** Використання інструментів перехоплення (Mitmproxy, Charles, Burp Suite) на рутованому пристрої користувача.
3. **Наслідки компрометації ключа:**
   - Зловмисник може використовувати ключ для власних сторонніх запитів і вичерпати місячний безкоштовний ліміт (100 000 викликів).
   - При вичерпанні ліміту сервер поверне `HTTP 429`, і користувачі бачитимуть закешовані дані до скидання місяця.
   - **Фінансовий ризик = СТРОГО $0.00:** Оскільки платіжна карта не вказується при реєстрації безкоштовного акаунту, фінансових збитків бути не може за жодних обставин.

### 4.2. Комплексний багаторівневий захист у межах бюджету $0 (Zero-Cost Defense-in-Depth)

1. **Рівень 1: Виключення з системи контролю версій (VCS Hygiene)**
   - Ключ ніколи не зберігається у вихідному коді Git.
   - Зберігається у локальному файлі `local.properties` (доданому в `.gitignore`) і генерується у `BuildConfig.WEATHERMETRO_KEY` під час компіляції.
2. **Рівень 2: Обфускація та мінімізація R8 / ProGuard**
   - У релізному білді увімкнено `isMinifyEnabled = true` та `isShrinkResources = true`.
   - Символьні назви класів та методів замінюються на випадкові послідовності літер, що ускладнює навігацію в декомпіляторі.
3. **Рівень 3: XOR-маскування бінарних байтів (Anti-Strings)**
   - Замість зберігання ключа як відкритого рядка в пулі констант DEX, ключ розбивається на байти і маскується операцією `XOR` із динамічним збиранням у пам'яті лише безпосередньо перед формуванням HTTP-запиту:
     ```kotlin
     private val MASK: ByteArray = byteArrayOf(0x5A, 0x3F, 0x1C, ...)
     private val ENCRYPTED_KEY: ByteArray = byteArrayOf(...)
     fun getApiKey(): String = String(ENCRYPTED_KEY.mapIndexed { i, b -> (b.toInt() xor MASK[i % MASK.size].toInt()).toByte() }.toByteArray())
     ```
   - Проста утиліта `strings` у скомпільованому APK повертає лише шум і не знаходить ключ.
4. **Рівень 4: Мережева ізоляція (Network Security Config)**
   - У `res/xml/network_security_config.xml` суворо заборонено відкритий трафік (`cleartextTrafficPermitted="false"`).
   - Запити дозволені виключно на офіційні домени `api.weathermetro.com` та `weather.visualcrossing.com`.
5. **Рівень 5: Агресивне клієнтське кешування та Stale-While-Revalidate**
   - Кешування у `WeatherLocalCache` на 30–60 хвилин знижує частоту викликів на 80%.
   - Захист від частих кліків (Debounce мінімум 30 секунд на pull-to-refresh).
6. **Рівень 6: Плавна деградація UI (Graceful Degradation)**
   - При коді `HTTP 429` (перевищення квоти) застосунок показує останній збережений прогноз із плашкою «Офлайн-дані» без помилок або крашів.
   - За потреби шар репозиторію автоматично переключається на резервне джерело (Кандидат №2 Visual Crossing).
