# Профіль проєкту / PROJECT_PROFILE

> Заповнює 🔧-параметри конституції v2.0. Не послаблює її. Значення «попередньо» є робочими технічними пропозиціями, а не продуктовим схваленням власника.

## 1. Проєкт

| Поле | Значення |
|---|---|
| Назва | Погода (робоча назва; бренд не визначено) |
| Опис | Android-застосунок прогнозу погоди з сучасним візуальним інтерфейсом, віджетом, погодинним і денним прогнозом до 14 днів, GPS-локацією за запитом і пошуком міста онлайн. |
| Ліцензія | Не визначена власником; не оголошувати проєкт відкритим чи пропрієтарним до рішення. |
| Головна гілка | `main` (попереднє стандартне значення) |
| Репозиторій | Ще не створений/не наданий. |

## 2. Власник

| Поле | Значення |
|---|---|
| Час | Не вказано; мінімізувати запити, зібрати рішення в `OWNER_INBOX.md`. |
| Технічний рівень | Не вказано; звіти писати простою українською й давати один конкретний крок власнику за повідомлення. |
| Мова звітів/чату | Українська. |
| Мова коду/ідентифікаторів | Англійська; документація для власника українською. |
| Часовий пояс | Europe/Warsaw. |

## 3. Автономія

- Рівень: за замовчуванням конституції — агенти можуть зливати зміни після незалежного `QA Verified` і зелених обов'язкових перевірок, якщо ці механізми доступні.
- `QA Verified`: лише окремий QA-агент або власник; автор не може перевіряти власну зміну.
- Рішення власника обов'язкове для переходу через етапні ворота та будь-якої зовнішньої публікації. Автоматичне злиття не означає автоматичного релізу.

## 4. Ролі / зони

| Роль | Зона | Може | Не може |
|---|---|---|---|
| Агент 0 — керівник | Весь проєкт, координація | Планувати в межах затвердженого обсягу, інтегрувати, вести журнали й inbox | Самостійно вирішувати комерційність, дозволи/збір даних, реліз або змінювати конституцію без прямої команди |

| Android UI | `app/**` UI та ресурси | Екрани, Compose-компоненти, анімації, стани віджета за контрактом | Змінювати мережеві дозволи/політику приватності чи API-контракт без узгодження |

| QA і приватність | План/перевірки, звіт | Незалежно перевіряти функціональність, дозволи, доступність, віджет і докази | Верифікувати авторську роботу самому або послаблювати перевірки |

## 5. Технології й середовище

- Стек: попередня пропозиція — Kotlin, Jetpack Compose, Android App Widget через Jetpack Glance, coroutines/Flow, локальний кеш; остаточне рішення — у технічному ADR після перевірки офіційної документації.
- Платформи: Android phone; підтримка конкретних версій ОС ще не визначена. Віджет Android обов'язковий до першого публічного релізу.
- Комп'ютер: Windows; Antigravity App/IDE (версія невідома).
- Пристрої: емулятор для розробки; фізичне тестування виконує власник, якщо доступне. Агент не заявляє, що перевіряв на реальному пристрої.
- Модулі: Android; Google Play поки не підключено й не затверджено.

## 6. Ліцензії та сторонні компоненти

- Реєстр: `docs/governance/THIRD_PARTY.md`.
- Дозволені: лише компоненти з підтвердженою сумісною ліцензією й офіційним першоджерелом.
- Умовні: погодні/геокодувальні API — лише після перевірки умов, атрибуції, квот, приватності та сценарію комерціалізації.
- Заборонені: невідомі ліцензії, заборона на потрібне використання, платні сервіси без окремого схвалення.
- Open-Meteo: кандидат для прототипу/некомерційного релізу; безкоштовний сервіс обмежений некомерційним використанням і вимагає атрибуції CC BY 4.0. Реклама/платна підписка означатимуть комерційний сценарій, який потребує іншого плану й рішення власника.

## 7. Лише Власник

- Акаунти/консолі: Google Play Console, хмарні/платіжні акаунти, секрети, репозиторні налаштування.
- Платні послуги: жодних без попереднього рішення.
- Публікація: лише власник; навіть внутрішнє тестування лише після його кроку в консолі.
- Наперед затверджено: нічого щодо реклами, аналітики, акаунтів, фонової локації, платних послуг, публікації чи додаткового збору даних.
- Власник визначає: ліцензію, бренд, комерційну модель, мінімальну Android-версію, релізний канал і перехід між фазами.

## 10. Посилення

- Не запитувати дозвіл локації при першому запуску автоматично; GPS — тільки після явного натискання користувача. Обробляти відмову й approximate location.
- Не застосовувати `ACCESS_BACKGROUND_LOCATION`, аналітику, рекламні SDK, акаунти чи збір координат без окремого попереднього рішення власника.
- Не зберігати точні координати в журналах, звітах або crash-даних.
- Кешувати прогноз локально для швидкого відкриття/офлайн-стану лише в мінімальному обсязі; показувати час останнього оновлення та застарілість даних.
- Основна анімація має поважати системну настройку зменшення руху. Віджет оновлювати в межах Android AppWidget механізмів, без безперервного опитування/анімації.
- Публічний реліз і будь-яка зміна затверджених продуктового обсягу, дозволів або моделі доходу — за рішенням власника.
