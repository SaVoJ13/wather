## [ADR-005] Стратегічне рішення Власника: Комерційна модель із рекламою (Ad-Supported)
- **Дата:** 2026-11-17
- **Статус:** Прийнято Власником (`Owner Approved`)
- **Контекст:** Власник визначив бізнес-модель застосунку: продукт буде комерційним і міститиме рекламу.
- **Аналіз наслідків:**
  1. **Погодний API для релізу:** Безкоштовний тариф Open-Meteo (CC BY 4.0) забороняє використання в застосунках із рекламою. Для фінального релізу потрібна комерційна ліцензія (Open-Meteo Commercial від €29/місяць або комерційний тариф іншого провайдера, наприклад WeatherAPI / OpenWeather).
  2. **Період розробки (Development / Testing):**
     - Розробка UI та бізнес-логіки ведеться на базі `MockWeatherRepository` та тестового адаптера без витрат коштів Власника.
     - Архітектурний контракт `WeatherRepository` повністю ізолює UI від конкретного провайдера, тому заміна API-джерела перед релізом не вимагатиме переписування інтерфейсу.
  3. **Рекламні блоки:**
     - На етапі розробки використовувати виключно офіційні тестові ідентифікатори Google Mobile Ads (AdMob Test Ad Unit IDs), щоб не порушувати правила Google щодо генерації недійсного трафіку.
     - Справжні рекламні ідентифікатори та акаунт AdMob підключаються виключно Власником перед публікацією (п. 3.2 Конституції).
     - Розміщення реклами в UI не повинно блокувати ключові погодні показники та не повинно порушувати правила розміщення Google Play. У домашньому віджеті (Glance AppWidget) реклама не розміщується (заборонено гайдлайнами Android).

## [ADR-002] Технічний стек платформи Android та версії інструментів
- **Дата:** 2026-11-17
- **Статус:** Прийнято (рішення Керівника за делегуванням)
- **Контекст:** Необхідно зафіксувати сучасний, стабільний та підтримуваний технічний стек для розробки UI, віджета та збереження даних.
- **Дослідження середовища розробника:**
  - Android Studio встановлено у `C:\Program Files\Android\Android Studio`.
  - Вбудований JDK: OpenJDK 25 (JBR) у `C:\Program Files\Android\Android Studio\jbr`.
  - Android SDK встановлено у `C:\Users\cocro\AppData\Local\Android\Sdk` (наявні платформи: `android-34`, `android-35`, `android-36`).
- **Рішення:**
  1. **Мова та середовище:** Kotlin 2.0+ з підтримкою Kotlin Multiplatform-ready архітектури (чисті domain/data моделі).
  2. **UI Toolkit:** Jetpack Compose (Material 3) з підтримкою Dynamic Color (Material You), світлої/темної тем та доступності (WCAG AA).
  3. **Віджет головного екрана:** Jetpack Glance (`androidx.glance:glance-appwidget`) — офіційний декларативний інструмент від Google для створення віджетів на базі Compose-парадигми.
  4. **Мережевий клієнт та серіалізація:** KotlinX Serialization JSON + Ktor Client / OkHttp (легковагові, безпечні рішення без надлишкових залежностей).
  5. **Асинхронність:** Kotlin Coroutines + Flow + StateFlow у ViewModel.
  6. **Локальний кеш:** AndroidX DataStore / SQLite Room для збереження кешу погоди та списку міст.
  7. **Версії цільової ОС (попередньо до затвердження Власником):**
     - `minSdk = 26` (Android 8.0 Oreo) — покриває >95% активних пристроїв у світі та підтримує сучасні Java 8+ / Time API без складного desugaring.
     - `compileSdk = 35`, `targetSdk = 35` (Android 15) — відповідає актуальним вимогам Google Play 2026 року.
- **Альтернативи відхилені:**
  - Класичні Android Views / XML layouts (застарілий підхід, значно складніший для анімованого погодного інтерфейсу).
  - Зовнішні фреймворки (Flutter/React Native) — суперечать початковим вимогам щодо чистого Android Compose застосунку з якісним Glance-віджетом.

## [ADR-003] Джерело погодних даних, геокодування та стратегія ізоляції API (Open-Meteo)
- **Дата:** 2026-11-17
- **Статус:** Прийнято (рішення Керівника за делегуванням)
- **Контекст:** Продукт вимагає 14-денного денного прогнозу, погодинного прогнозу та пошуку міст. Необхідно дотриматися ліцензійних умов та забезпечити безперебійну розробку до фінального рішення Власника щодо бізнес-моделі.
- **Аналіз першоджерел:**
  - **Open-Meteo:** Надає прогноз до 16 днів, погодинні дані, погодні коди WMO, високу швидкість відповіді, не вимагає API-ключів для базового доступу.
  - **Умови використання Open-Meteo (Terms):** Безкоштовний API призначений *виключно для некомерційного використання* та вимагає обов'язкової атрибуції (ліцензія CC BY 4.0). Використання в комерційних застосунках (з платними підписками, платним завантаженням або рекламою) вимагає комерційної підписки.
- **Рішення:**
  1. Для Фази 1-3 використовувати Open-Meteo як базове некомерційне джерело для прототипування та тестування.
  2. В обов'язковому порядку реалізувати шар `WeatherRepository` та `GeocodingRepository` за патерном Repository / Adapter, повністю ізолювавши специфічні DTO Open-Meteo від доменних моделей (`WeatherData`, `ForecastDay`, `HourlyForecast`, `LocationItem`).
  3. Для UI та тестів розробити повноцінний `MockWeatherRepository` з локальними фікстурами реалістичної погоди для Києва, Варшави, Лондона тощо. Це дозволить розробляти UI автономно та без мережевих затримок.
  4. Зафіксувати питання комерційної ліцензії в `OWNER_INBOX.md`. До рішення Власника заборонено додавати будь-яку комерціалізацію.

## [ADR-004] Політика приватності геопозиції та незалежність пошуку від GPS
- **Дата:** 2026-11-17
- **Статус:** Прийнято (рішення Керівника за делегуванням)
- **Контекст:** Застосунок повинен визначати поточне місце користувача та підтримувати пошук будь-якого міста світу.
- **Рішення:**
  1. **Явний контекстний запит:** Запит дозволу на визначення геопозиції (`ACCESS_COARSE_LOCATION` / `ACCESS_FINE_LOCATION`) відображається **виключно** при натисканні користувачем кнопки «Моє місцезнаходження» або відповідного перемикача. Заборонено запитувати дозвіл при першому запуску застосунку без попереднього пояснення.
  2. **Повна незалежність пошуку:** Пошук міст через онлайн-геокодування та вибір міста зі списку працює абсолютно автономно і не потребує жодних дозволів геолокації. Якщо користувач відхиляє запит на доступ до GPS, застосунок штатно функціонує з вибраним вручну містом.
  3. **Сувора заборона фонової локації:** Дозвіл `ACCESS_BACKGROUND_LOCATION` не оголошується в `AndroidManifest.xml` і ніколи не запитується.
  4. **Конфіденційність даних:** Координати користувача ніколи не передаються стороннім аналітичним службам і не записуються в персистентні логи.
