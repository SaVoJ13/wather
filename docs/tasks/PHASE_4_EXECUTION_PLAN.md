## 1. Мета та огляд етапу Phase 4

**Головна мета Phase 4:** Реалізувати, протестувати та верифікувати повноцінний інтерфейс Android-застосунку погоди на Jetpack Compose суворо за затвердженими специфікаціями та дизайн-системою Phase 1, з підтримкою трьох вкладок навігації («Зараз», «Прогноз», «Місця»), окремого екрана налаштувань через TopBar, повної відсутності фальшивих погодних даних/радара/GPS, проведенням інструментального тестування на Android-емуляторі/пристрої та фіксацією фактичних скриншотів для Власника.

## 2. Непорушні обмеження та Червоні лінії (Constitution v2.0)

1. **Заборона самоверифікації (п. 2.1, Червона лінія №9):** Автор коду не ставить `QA Verified` на власну роботу. Верифікацію кожного блоку здійснює незалежний аудитор **Agent 5 (`qa-privacy`)**.
2. **Бюджет $0.00 (п. 3.2):** Жодних платних сервісів, підписок чи платіжних профілів.
3. **Приватність геолокації (ADR-004, ADR-015):** 
   - 0 автоматичного визначення GPS при запуску або перемиканні вкладок.
   - Визначення локації — **виключно за явним кліком** користувача по іконці «Моє місце».
   - Сувора відсутність `ACCESS_BACKGROUND_LOCATION`.
   - Пошук міст на 100% функціонує без дозволу GPS.
4. **Достовірність метеоданих (Data Integrity):**
   - Жодних вигаданих значень (1013.25 гПа, 50%, 0.0 мм, temp).
   - Необов'язкові метрики позначаються як «Немає даних» (`R.string.no_data`).
   - Усунення ризику усікання дробових WMO-кодів (наприклад, 0.5 не перетворюється на 0 Clear Sky).
   - Жодного фіктивного LIVE-радара в MVP (радар вилучено за рішенням Phase 1).
5. **Тестування на Android:**
   - Обов'язковий запуск інструментального тесту `WeatherLocalCacheAndroidTest` на Android-емуляторі або підключеному пристрої (не лише компіляція APK).
6. **Зупинка перед Phase 5:**
   - Жодних передоплат чи активації бойової реклами (лише тестові ID AdMob).
   - Не переходити до Phase 5 без окремого рішення Власника (`Owner Approved`).

### 3.1. Agent 0: Lead Architect & Technical Project Manager
- **TASK-045: Координація Phase 4 та governance-пам'ять:**
  - Фіксація рішень `ADR-015` у `DECISIONS.md`, оновлення `CURRENT_STATE.md`, створення `PHASE_4_EXECUTION_PLAN.md`.
  - Моніторинг стабільності компіляції (`gradlew`) та зелений CI на гілці `main`.
- **TASK-046: Захист архітектурних контрактів Clean Architecture:**
  - Контроль ізоляції шарів (Domain, Data, Presentation) у нових та оновлених компонентах Compose.
  - Контроль відсутності бізнес-логіки всередині UI-компонентів.

### 3.2. Agent 1: Product & UX Designer (`product-ux`)
- **TASK-047: UX-аудит відповідності макетам Phase 1:**
  - Перевірка навігаційної моделі: 3 вкладки («Зараз», «Прогноз», «Місця») та екран «Налаштування» через TopBar.
  - Перевірка ергономіки One-Handed Thumb Zone та розташування ключових дій у нижній/середній частині екрана.
- **TASK-048: Доступність (Accessibility & Inclusivity):**
  - Перевірка контрастності всіх текстових елементів та бейджів (WCAG AA ≥ 4.5:1).
  - Перевірка мінімальних розмірів інтерактивних елементів (тач-таргети ≥ 48x48 dp).
  - Підтримка TalkBack семантики українською та всіма підтримуваними мовами.
  - Підтримка системного прапорця `reduced-motion` (спрощення анімацій переходів до 100 мс, вимкнення циклічних ефектів).

### 3.3. Agent 2: Android UI Engineer (`android-ui`)
- **TASK-049: Полірування та стабільність вкладок «Зараз», «Прогноз», «Місця»:**
  - **Вкладка 1 («Зараз»):** Hero-блок із великою температурою, 24-годинна стрічка (від поточної локальної години), сітка метрик 2x2 («Немає даних» для відсутніх полів), дуга сходу/заходу сонця на Canvas, плашка правової атрибуції.
  - **Вкладка 2 («Прогноз»):** 14–16 днів із кольоровими Range Bars температури, відкриття модального вікна `DayDetailsBottomSheet` за тапом на день.
  - **Вкладка 3 («Місця»):** Управління збереженими містами (до 10 міст), швидкий вибір, кнопка пошуку та ручний запит GPS.
- **TASK-050: Окремий екран «Налаштування» (SettingsScreen):**
  - Доступний через іконку шестерні у `WeatherTopBar`.
  - Містить перегляд поточної мови, правові посилання, політику конфіденційності, атрибуцію та системні налаштування.
- **TASK-051: Обробка станів екрана (State Management):**
  - `Loading`: `WeatherLoadingSkeleton` без стрибків макета.
  - `Success`: Повноцінний інтерфейс із Pull-to-Refresh.
  - `Offline / Stale`: Відображення збереженого кешу з інформаційною плашкою «Офлайн-режим (застарілі дані)».
  - `Error`: `WeatherErrorScreen` із можливістю повторної спроби («Спробувати знову»), якщо кеш відсутній.

### 3.4. Agent 3: Weather & Location Engineer (`weather-location`)
- **TASK-052: Цілісність числових та WMO даних (Data Integrity Guard):**
  - Повне усунення ризику перетворення дробових чисел (0.5, 1.2) у 0 (Clear Sky) у `WeatherMetroHttpClient.kt`.
  - Сувора валідація WMO-кодів: Clear Sky виключно для числового 0.
- **TASK-053: Ізоляція міст та часові пояси:**
  - Скасування in-flight запитів при перемиканні міст (`fetchForecastJob?.cancel()`).
  - Підтримка коректного локального часу вибраного міста під час переходів між вкладками.

### 3.5. Agent 4: Widget & Monetization Engineer (`widget-monetization`)
- **TASK-054: Перевірка рекламного контейнера (Zero CLS):**
  - Контейнер `AdBannerPlaceholder` фіксованої висоти 60.dp у нижній частині `Scaffold` над NavigationBar.
  - Повна відсутність зсувів контенту (Zero Cumulative Layout Shift) під час завантаження реклами.
  - Використання виключно тестових AdMob Ad Unit ID.
- **TASK-055: Синхронізація з Glance-віджетом:**
  - Миттєве оновлення віджета на робочому столі (`WeatherWidgetScheduler.updateWidgetNow`) при виборі нового міста в застосунку.

### 3.6. Agent 5: QA & Privacy Specialist (`qa-privacy`)
- **TASK-056: Запуск інструментальних тестів на емуляторі/пристрої:**
  - Запуск Android-емулятора (`small_phone`) через Android SDK.
  - Виконання інструментального тесту `WeatherLocalCacheAndroidTest` за допомогою `connectedDebugAndroidTest`.
  - Фіксація реального дискового збереження та відновлення після перезапуску процесу.
- **TASK-057: Створення скриншотів інтерфейсу (Visual Evidence):**
  - Зняття скриншотів усіх 3 вкладок («Зараз», «Прогноз», «Місця»), деталей дня та екрана налаштувань.
  - Порівняння фактичного інтерфейсу із затвердженими макетами Phase 1.
- **TASK-058: Повний аудит та фінальний звіт:**
  - Запуск unit-тестів (Debug та Release), Android Lint (`abortOnError = true`).
  - Формування підсумкового звіту `PHASE_4_QA_REPORT.md` та звіту воріт `PHASE_GATE_4.md`.
