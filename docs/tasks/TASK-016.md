## Критерії приймання (Acceptance Criteria)

1. [x] Спроєктовано інформаційну архітектуру застосунку навколо трьох ключових розділів:
   - Розділ 1: «Зараз» (Поточна погода Hero, 24h погодинний ряд від поточної години, сітка ключових метрик 2x2, анімована Canvas-дуга сходу/заходу сонця, динамічна атрибуція API).
   - Розділ 2: «Прогноз» (Повний 16-денний прогноз, інтерактивний сплайн-графік температур із мікро-тултіпом, стовпчикова гістограма опадів, тренди тиску/вітру, розкриття деталей обраного дня).
   - Розділ 3: «Місця & Радар» (Управління збереженими містами, онлайн-пошук з 400 мс дебаунсом + офлайн-база, одноразова кнопка «Моє місцезнаходження» за явним кліком, інтерактивний LIVE-радар 360° із кільцями 15/30/50 км та таймлайном, вибір одиниць та 8 мов).
2. [x] Детально описано повні користувацькі сценарії (User Flows 1–9):
   - Flow 1: Перший запуск (Zero intrusive permissions, дефолтне місто за регіоном, системна мова).
   - Flow 2: Пошук населених пунктів, збереження та видалення з обраного (з механізмом Undo).
   - Flow 3: Одноразовий GPS за явною дією (Rationale Dialog, Coarse/Fine, м'яка обробка відмови, Zero Background Location).
   - Flow 4: Взаємодія з графіками та аналітикою на 16 днів.
   - Flow 5: Інспекція погодного радара (360° sweep-промінь, шкала інтенсивності опадів, Play/Pause, таймлайн) та астрономічних даних.
   - Flow 6: Перемикання мови інтерфейсу (8 опцій: uk, pl, en, de, es, it, ru, default).
   - Flow 7: Життєвий цикл та поведінка віджетів 2x2 та 4x2 (Glassmorphism, нуль реклами, автооновлення через AlarmManager).
   - Flow 8: Офлайн-робота, повернення мережі та обробка HTTP 429 (Too Many Requests).
   - Flow 9: Слот банера Google AdMob у нижній частині (Zero CLS, фіксована висота, заборона реклами у віджетах).
3. [x] Зафіксовано критерії доступності WCAG 2.1 AA:
   - Контрастність тексту ≥ 4.5:1 (для великих чисел ≥ 3.0:1).
   - Мінімальні тач-таргети ≥ 48x48dp.
   - Семантичні підписи TalkBack рідною мовою для всіх погодних елементів.
   - Dynamic Type масштабування до 200%.
   - Поведінка системного режиму Reduced Motion (відключення обертання радара, дуги сонця та заміна Shimmer на статичні блоки).
4. [x] Дотримано політику $0 додаткового бюджету (Zero Budget Policy) та збережено непорушність доменних/API контрактів.
5. [x] Синхронізовано специфікацію `docs/ux/UX_SPEC.md` із новим документом `docs/ux/USER_FLOWS.md`.
